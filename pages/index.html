Why GitLab

为什么让 AI
通过 GitLab 工作

GitLab 不只是放文件的地方。它给 AI 一套熟悉的入口，把资料、协作、自动执行和每次修改的来龙去脉放在一起，让 AI 更容易理解，也让人更容易检查。

01 · AI 熟悉的入口

不用为每个项目
重新教 AI

GitLab 自带命令行和接口，AI 已经理解这套通用用法：找到项目、读取资料、提交修改，都有现成的路径。

02 · 从资料到执行

把协作过程
自然串起来

知识库、页面、自动检查、机器人和执行环境可以接在一起，让 Agent 从“读懂”一路走到“完成并交付”。

03 · 唯一真理源

AI 最近的
可信入口

项目仓库保存当前版本、修改记录和讨论依据。大家看同一份内容，AI 也从这里开始，不再反复寻找“到底哪份是真的”。

Simple SOP

从新建项目，
到安全合入

第一次完成登录、令牌和业务项目配置。之后每个任务都遵循同一条路径：从正式版本开新分支，修改并检查，通过合并请求确认后再合入。

01
首次配置 · 先登录，再创建令牌

登录 GitLab，创建个人访问令牌

按下面 1–4 步操作。右侧图示也要跟着点击切换 Tab 查看，不同 Tab 对应不同页面位置。

  1. 先登录。打开 GitLab 群组或项目页面；如果右上角显示 Sign in，先完成公司账号认证。
  2. 找到入口。登录后打开个人设置，进入“访问”，再点击“个人访问令牌”。
  3. 选择令牌类型。点击“生成令牌”，选择“旧版令牌”，填写名称和到期日。
  4. 设置并复制。按团队要求只勾选完成工作所需的权限，生成后立即复制令牌；离开页面后通常无法再次查看。

02
每个新业务做一次 · 进入统一目录

在指定 Group 创建业务项目

点击“新建项目”，选择“创建空白项目”。所有业务项目必须进入组织指定的同一个 Group，不能散落在个人空间。项目命名应让别人一眼看懂业务；初始化 README，让项目从第一天就有说明、负责人和正式分支。

  1. 项目名称。使用清晰、稳定的业务名，例如 note-design-knowledge。
  2. 统一 Group。命名空间选择组织指定的业务知识库 Group；没有权限时联系 Group Owner 建仓或授权。
  3. 可见范围。遵循 Group 的统一策略，不由个人随意改成公开；含业务资料时默认使用组织批准的范围。
  4. 初始化说明。勾选 README，创建后写清业务范围、负责人、维护状态和使用方式。

04
交给 AI · clone 并检查项目

把信息交给 AI

提供用户名、PAT 和项目 HTTPS 地址。AI 应先检查 Git，再 clone 项目并验证当前分支、远端地址和仓库状态，最后读取 README、AGENTS.md 等项目规则。

仅限

本地、受信任且能够操作终端的 AI 工具。

完成标志

git status 正常，AI 已读懂项目规则。

直接复制给 AI · CLONE 项目
请帮我把一个 GitLab 项目 clone 到当前工作区。

GitLab 用户名：<用户名>
Personal Access Token：<刚创建的令牌>
Clone with HTTPS：<项目 HTTPS 地址>

请按顺序完成：
1. 检查 git --version；如果 Git 未安装或 user.name / user.email 未配置，先告诉我。
2. 使用以上信息完成认证并 clone 项目。不要回显令牌，不要把令牌写入 URL、仓库、配置文件、日志或聊天摘要。
3. 进入项目后运行 git status、git remote -v、git branch --show-current。
4. 读取 README、AGENTS.md、CONTRIBUTING 和其他项目说明。
5. 最后告诉我 clone 是否成功、当前分支和需要遵守的项目规则。

现在不要修改、提交或推送任何内容。
令牌只用于当前本地认证；不要提交到 GitLab。
05
每个任务都要做 · 不直接改正式版本

从最新版本创建任务分支

main 代表大家正在使用的正式版本。每次新需求都从最新的 main 创建一个短期任务分支，完成后再申请合入；这样修改未确认时不会影响其他人。

分支命名

feat/主题、fix/主题、docs/主题。

基本原则

一个任务一个分支；合入后删除任务分支。

ONE TASK · ONE BRANCH · REVIEW BEFORE MERGE

07
合入规范 · 让正式版本可追溯

发起合并请求，审核后进入 main

合并请求不是形式流程，而是一次集中确认：为什么改、改了什么、怎么证明可用、还有什么风险。信息不完整、检查未通过或审核意见未解决时，不合入正式版本。

  1. 标题说结果。例如“新增首次登录的新建项目指引”，不要只写“更新”。
  2. 说明范围。写清目标、主要变化、未包含内容和影响范围。
  3. 提供证据。附检查结果；视觉变化附预览或截图，复杂流程说明验证方法。
  4. 解决意见再合入。至少由相关负责人检查；自动检查通过、意见关闭后再合并，并删除任务分支。
禁止

绕过审核直接推送 main；把多个无关任务塞进一次合入。

完成标志

main 包含已确认修改，任务分支已删除，记录仍可查询。
